# HMI 布局规则

本文件只定义布局安全、对齐、边界、元素避让、HTML 页面、原生组件与 HTML 混合页面及动态元素布局规则。

它不定义固定主题、固定颜色、固定字号、固定边距、固定间距、固定按钮尺寸或固定页面模板。所有尺寸、位置、颜色、字体、主题、布局风格和组件数量都可以由用户在自然语言需求中明确指定；用户明确要求的内容优先于本文件。

字段合法性、组件类型、层级结构和 JSON 结构必须以 `schema.md` 为准。

## 1. 用户要求优先

- 用户明确指定画布尺寸、组件位置、组件尺寸、HTML 页面结构、颜色、字体、主题、排列方式或页面结构时，必须优先执行用户要求。
- 用户可以要求浅色、深色、特定颜色、紧凑布局、留白布局、左右排列、上下排列、居中、网格排列或任意明确布局方式。
- 用户要求不能违反 `schema.md` 的字段、组件类型、层级和数据结构约束。
- 用户明确要求两个组件或 HTML 页面元素叠加时，仅当该叠加不遮挡关键交互、不导致文字不可读且不违反 Schema 时允许执行。
- 用户明确要求原生组件、HTML 或混合页面的区域位置时，必须优先执行。

## 2. 自动布局原则

当用户没有提供完整位置或尺寸时：

- 根据画布尺寸、组件数量、组件默认尺寸、组件功能和内容长度动态安排布局。
- 先规划功能区域，再放置组件或 HTML 内容；不要先随意生成坐标。
- 优先保持同一功能组内的组件在视觉上相邻。
- 优先使同类组件保持对齐、尺寸一致和间距一致。
- 空间不足时，优先重新排列、拆分功能区、减少非关键预览元素或使用 `node:tabView`；不得为了容纳更多元素而让普通组件相互覆盖。
- 未指定原生组件主题、颜色或样式时，使用该组件在已验证 JSON 示例或 `component-schema.json` 中已有的字段和值；不得强制额外主题方案。
- 用户未指定原生组件、HTML 或混合实现方式时：
  - 现场 PLC 控制、变量绑定、参数设定、报警确认、仪表、趋势和标准工艺控制优先规划为原生组件区域。
  - 复杂展示、复杂报表、第三方 API、摄像头、外部系统、iframe 和网页化交互优先规划为 HTML 区域。
  - 同时存在两类需求时，规划原生控制/工艺区与 HTML 展示/外部数据区。

## 3. 元素边界

- 所有原生组件的几何包围盒必须位于所属画布或所属合法父节点的可用范围内。
- 对可能具有描边、文字、选中框、图片或视觉外扩效果的组件，应避免紧贴画布边缘。
- 不得让文字、按钮、输入框、输出框、图表、仪表、表格或工艺图形被画布边界裁剪。
- 当用户明确指定靠边布局时，仍应确保组件本体和关键文字可见。
- HTML 可见内容、iframe、HTML 图表、HTML 弹窗、HTML 动画和第三方网页内容也必须适配画布可见区域。
- HTML 页面不得产生无意义的水平滚动条、超出画布的关键内容或无法操作的关键交互区。
- HTML 内容内部允许滚动时，滚动区域必须明确，且不能使页面主要控制区域不可见。

## 4. 普通组件不得重叠

除“合法工艺重叠”外，以下普通组件之间不得发生包围盒交叉：

- 按钮、开关、复选框、输入框、输出框、选择器、滑动条。
- 文本、标签、单位文字、标题、说明文字。
- 仪表、进度条、趋势图、XY 图、表格。
- 不属于同一个复合工艺对象的基础图形。

布局时应确保：

- 文本不覆盖按钮、输入框、输出框、仪表、图表或表格。
- 两个交互组件不相交。
- 标签、读数和单位文字之间不相互覆盖。
- 不同功能区域的普通组件不相交。
- 容器背景或边框不遮挡其视觉区域上的组件。
- 原生 PLC 控件不与其他原生组件发生不可用的重叠。
- HTML 页面中的关键文字、HTML 按钮、表格、图表和交互元素不发生不可读或不可点击的重叠。

若两个普通组件的矩形包围盒存在交叉面积，则应重新布局；仅边缘接触时，也应优先保留可见间隔，除非用户明确要求紧贴。

## 5. 合法工艺重叠

以下具有明确工艺语义的重叠允许存在：

- `base:circle` 滚筒位于输送带 `base:rect` 两端。
- `base:polyline` 的流动虚线位于输送带、管道或工艺路径上。
- 表示液面的图形位于水箱、储罐或容器轮廓内部。
- 阀门、泵、电机等复合工艺对象由多个基础图形组成。
- 状态灯、运行标识或局部标签紧邻或叠加在设备图标附近。
- `node:container` 作为底层背景，根级普通组件覆盖在其视觉区域内。
- HTML 中用于表达设备、管线、液面、流向、状态或数据关系的 SVG、Canvas、CSS 图层可进行合理的局部重叠。

合法工艺重叠必须满足：

- 叠加用于表达设备结构、工艺介质、流向、状态或层次关系。
- 关键控制与关键文本仍然可见、可读、可操作。
- 组件层级顺序合理：背景/外壳在前，介质/路径在中，状态/文字在后。
- `base:shape` 与 `base:polyline` 仍满足 `schema.md` 的 points、segments、pointsSize 规则。
- HTML 内的局部重叠不得遮挡其所属工艺对象的关键读数、报警文字或交互区域。

## 6. 分组与对齐

- 同一控制组中的按钮、开关、输入框和输出框应优先对齐。
- 相同功能的组件应优先使用相同尺寸；用户明确指定不同尺寸时按用户要求执行。
- 同一组标签应优先左对齐或右对齐；同一组读数框应优先对齐。
- 状态灯与对应状态文字应组成清晰的相邻关系。
- 当用户要求“并排”“上下排列”“居中”“靠左”“靠右”“顶部”“底部”等布局时，按其语义保持对齐与顺序。
- 当用户未指定布局时，应以功能关系、阅读顺序和避免重叠为依据自动排列。
- 原生控制组件应按操作顺序和工艺顺序排列，例如启动/停止、设定/确认、状态/报警。
- HTML 卡片、HTML 数据表、图表和外部数据区域应保持标题、筛选区、内容区、状态区之间的清晰结构。

## 7. 容器和页签

- `node:container` 只作为根级背景、边框或视觉分组区域使用。
- 普通组件不能放入 `node:container.children`；它们必须与容器并列放在 `graph.children` 中。
- 容器必须先于覆盖其视觉区域的组件出现在 `graph.children` 中，以确保容器作为底层背景。
- 信息量无法在同一画布内清晰呈现时，可使用 `node:tabView` 拆分页面。
- `node:tabView`、`node:tab` 的嵌套关系必须严格遵守 `schema.md`。
- 使用页签时，应将相关的原生工艺控制、参数设定和状态展示放在同一业务页签中。
- 当 HTML 报表、第三方系统、摄像头或复杂分析内容占用较大空间时，可将其放入独立页签；但用户明确要求同页混合时，应按用户要求使用混合页面布局。

## 8. HTML 页面布局

- `graph.htmlCode` 本身没有原生 `position` 和 `size` 字段；HTML 页面应通过标准 HTML/CSS 布局适配画布可见区域。
- 完整 HTML 文档或头部/正文片段均可按渲染器已验证方式生成。
- CSS 通常放在 `<head>` 的 `<style>` 中，页面结构和脚本通常放在 `<body>` 中。
- HTML 可以使用卡片、网格、表格、表单、图表、SVG、Canvas、动画、iframe 和外部库实现复杂展示。
- HTML 可见内容不得超出画布、遮挡关键原生控件或破坏用户指定布局。
- HTML 内部可以使用合理嵌套、卡片、网格、表格、表单和局部视觉重叠，但关键文字、按钮、读数必须可见、可操作。
- iframe 宽高和页面内容应适配可用画布。
- 目标网站加载失败或拒绝被嵌入时，不得视为 iframe 内容布局成功。
- HTML 的动画、图表、脚本更新和外部库渲染在任何状态下均不得裁剪关键内容或覆盖关键控制。
- HTML 没有已确认的第三方接口配置时，应展示接口占位、模拟数据或设计预览，不得伪造成现场 PLC 实时数据。

## 9. 原生组件与 HTML 混合页面布局

- `graph.children` 与 `graph.htmlCode` 已验证支持同页共同渲染，可以混合生成。
- 原生组件负责现场 PLC 控制、变量绑定、设备启停、参数输入、报警确认、现场状态、仪表、趋势和工艺控制。
- HTML 负责复杂展示、复杂报表、统计图、筛选表格、时间轴、摄像头、第三方 API、外部系统、iframe 和网页化交互。
- HTML 当前不读取、不订阅、不写入、不控制现场 PLC 变量，也不访问原生组件已绑定的 PLC 变量。
- 原生组件与 HTML 可以在同一页面并列、上下分区或按用户明确布局共同显示。
- 用户未指定混合布局时，应按功能关系划分清晰区域，例如：
  - 左侧原生控制区，右侧 HTML 报表或第三方数据区。
  - 上方原生工艺控制区，下方 HTML 分析、报表或趋势展示区。
  - 中央原生工艺图，侧边 HTML 摄像头、外部系统或统计信息区。
- HTML 不得遮挡原生按钮、输入框、报警确认、关键读数、工艺操作区或原生工艺动画。
- 原生组件的 PLC 数据与 HTML 的第三方数据、模拟数据或设计预览必须具有明确边界。
- 不得把 HTML 模拟数据、第三方 API 数据或外部系统数据伪造成原生组件 PLC 实时数据。
- 若用户明确要求同一业务页面既有 PLC 控制又有复杂报表、摄像头、第三方系统或外部数据，应优先规划混合页面，而不是删除任一侧功能。
- 混合页面中的 HTML 区域可作为独立展示面板，但不得影响原生控制区的操作和可读性。
- HTML 内部弹窗、悬浮卡片、全屏图表、iframe 和滚动容器不得覆盖原生 PLC 控制区域。
- 混合页面中的原生组件与 HTML 内容应在视觉上清晰区分，但可使用统一的用户指定主题、颜色或排版风格。

## 10. 动态元素布局

- 动态原生组件在其所有可见状态下均不得超出画布、遮挡关键文字或覆盖其他普通组件。
- 流动路径、液面、旋转标识和状态强调等动态视觉层可与所属工艺对象合法重叠，但不得覆盖该对象的关键控制、关键读数或报警文字。
- 为动态文本、读数变化和状态切换预留足够显示空间，避免状态变化后产生裁剪或重叠。
- 同一功能区域中的动态效果应保持清晰的视觉层级；背景、工艺主体、动态介质或路径、状态标识与文字应按其可读性安排层级。
- HTML 中可使用 CSS 动画、JavaScript 定时器、SVG、Canvas 或外部库实现第三方数据展示和设计预览动态。
- HTML 动态不得表现为未接入的现场 PLC 实时状态。
- 摄像头、外部系统和第三方 API 数据的加载状态、失败状态和占位状态应清晰显示，不得以静态内容冒充实时连接成功。
- 同一视图中不应让过多持续动画同时争夺注意力；动态效果应服务于工艺、第三方数据状态或明确交互反馈。

## 11. 输出前布局检查

输出 JSON 前，必须检查：

1. 用户明确要求的尺寸、位置、主题、HTML、混合模式和布局已被优先执行。
2. 所有原生组件在画布或合法父节点范围内。
3. 所有 HTML 可见内容、iframe、图表、动画和外部页面内容适配画布可见区域。
4. 普通组件之间不存在包围盒交叉。
5. 所有文本可读，未被控件、HTML、图表、仪表或画布边界遮挡。
6. 合法重叠仅用于工艺复合图形、流向、液面、状态标识、HTML 工艺图层或容器背景。
7. 原生 PLC 控制、参数输入、报警确认、关键读数和工艺操作区未被 HTML 内容遮挡。
8. HTML 内部弹窗、iframe、滚动区域、图表和动态内容未与原生控制区发生点击、滚动或视觉冲突。
9. HTML 模拟数据、第三方 API 数据和外部系统数据未被伪造成 PLC 实时数据。
10. 动态元素在全部可见状态下均未越界、未裁剪、未遮挡关键文字、关键读数或关键控制。
11. 同组组件保持合理的对齐和顺序。
12. 空间不足时已重新布局、分组或使用页签，而不是制造重叠。
13. 所有布局结果仍严格符合 `schema.md`。
