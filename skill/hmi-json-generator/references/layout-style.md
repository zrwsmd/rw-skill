# HMI 布局规则

本文件只定义原生组件层的布局安全、对齐、边界、元素避让、HTML 页面层布局、原生组件与 HTML 混合页面规则及动态元素布局规则。

它不定义固定主题、固定颜色、固定字号、固定边距、固定间距、固定按钮尺寸或固定页面模板。所有尺寸、位置、颜色、字体、主题、布局风格和组件数量都可以由用户在自然语言需求中明确指定；用户明确要求的内容优先于本文件。

字段合法性、组件类型、层级结构和 JSON 结构必须以 `schema.md` 为准。

## 1. 用户要求优先

- 用户明确指定画布尺寸、原生组件位置、原生组件尺寸、HTML 页面结构、颜色、字体、主题、排列方式或页面结构时，必须优先执行用户要求。
- 用户可以分别指定某一个渲染层内部的浅色、深色、特定颜色、紧凑布局、留白布局、左右排列、上下排列、居中、网格排列或其他布局方式；这些要求只作用于该层内部。
- 用户要求不能违反 `schema.md` 的字段、组件类型、层级和数据结构约束。
- 用户明确要求两个原生组件或两个 HTML 页面元素叠加时，仅当该叠加不遮挡同层关键交互、不导致同层文字不可读且不违反 Schema 时允许执行。
- 用户明确要求原生组件、HTML 或混合页面的页面结构时，必须优先执行。

## 2. 自动布局原则

当用户没有提供完整位置或尺寸时：

- 根据画布尺寸、组件数量、组件默认尺寸、组件功能和内容长度动态安排各自渲染层内的布局。
- 规划原生组件层时假设 HTML 层不存在，只按原生功能生成坐标；规划 HTML 页面层时假设原生组件层不存在，只按 HTML 内容组织页面。
- 优先保持同一功能组内的原生组件在视觉上相邻。
- 优先使同类原生组件保持对齐、尺寸一致和间距一致。
- 原生组件层空间不足时，优先重新排列、拆分功能区、减少非关键预览元素或使用 `node:tabView`；不得为了容纳更多元素而让普通原生组件相互覆盖。
- HTML 页面层空间不足时，优先使用响应式网格、换行、折叠、分页、明确的内部滚动区域或信息层级调整；不得使 HTML 内部关键内容不可读、不可见或不可操作。
- 未指定原生组件主题、颜色或样式时，使用该组件在已验证 JSON 示例或 `component-schema.json` 中已有的字段和值；不得强制额外主题方案。
- 用户未指定原生组件、HTML 或混合实现方式时：
  - 现场 PLC 控制、变量绑定、参数设定、报警确认、仪表、趋势和标准工艺控制优先使用原生组件。
  - 复杂展示、复杂报表、第三方 API、摄像头、外部系统、iframe 和网页化交互优先使用 HTML。
  - 同时存在两类需求时，且 `schema.md` 已确认 `graph.children` 与 `graph.htmlCode` 可并列存在，应选择混合页面，并把两层分别生成成独立、完整的结果；不得建立左右、上下、侧边或其他跨层空间关系。

## 3. 渲染层边界

- `graph.children` 与 `graph.htmlCode` 是完全独立的渲染层，只是在同一个 `graph` JSON 中并列保存，不是同一图层或同一画布中的两个区域。
- 处理任一层时必须假设另一层不存在；每层按自身需求正常使用自己的完整画布或视口。
- 禁止跨层读取或参考坐标、尺寸和布局，禁止为另一层避让、留白、缩小内容或预留区域。
- 禁止把两层划分为左右、上下、侧边、卡片区或页签区；这类布局词只允许描述某一个渲染层内部的排列。
- 原生组件层与 HTML 页面层之间不执行包围盒碰撞检测、互相遮挡校验、点击冲突校验或滚动冲突校验。
- 原生组件仅在 `graph.children` 所属层内执行边界、不重叠、可读性和可操作性检查。
- HTML 内容仅在 `graph.htmlCode` 所属层内执行页面边界、内部不重叠、可读性、可操作性和滚动检查。
- 独立渲染层不代表数据互通。HTML 不读取、不订阅、不写入、不控制现场 PLC 变量，也不访问原生组件已绑定的 PLC 变量，除非 Schema 或已验证接口明确另有定义。

## 4. 原生组件层边界

- 所有原生组件的几何包围盒必须位于所属画布或所属合法父节点的可用范围内。
- 对可能具有描边、文字、选中框、图片或视觉外扩效果的原生组件，应避免紧贴画布边缘。
- 不得让原生文字、按钮、输入框、输出框、图表、仪表、表格或工艺图形被原生画布边界裁剪。
- 当用户明确指定靠边布局时，仍应确保原生组件本体和关键文字可见。

### 4.1 宿主编辑器视口安全区

原生 Graph 的坐标边界与宿主编辑器的实际可视边界不是同一件事。工具栏、工具箱、属性面板、缩放和平移可能使一个在 JSON 中完全位于画布内的组件仍然被屏幕裁切。

用户未明确提供画布尺寸或宿主可视区参数时：

- `graph.size` 必须使用已验证默认值 `800×600`。
- 禁止根据显示器分辨率、截图宽高、常见 16:9 比例或内容数量自行扩大根画布。
- 原生层关键内容使用以下保守安全区：
  - `safeInsetX = max(32, round(graph.size.width × 0.06))`
  - `safeInsetY = max(32, round(graph.size.height × 0.06))`
  - 关键内容必须满足 `x >= safeInsetX`、`y >= safeInsetY`、`x + width <= graph.size.width - safeInsetX`、`y + height <= graph.size.height - safeInsetY`。
- 关键内容包括标题、正文、读数、设备主体、状态灯、按钮、开关、输入输出控件、图表和表格。
- 纯背景 `node:container`、全画布底色以及表达明确工艺连接关系的路径可以延伸到安全区之外，但不得承载会被裁切的关键文字或交互。

空间不足时：

- 重新安排单列/多行布局、缩短说明文字、减少非关键预览项或使用 `node:tabView`。
- 不得先生成大画布，再通过统一乘以某个比例机械缩放所有节点。全局缩放会同时缩小文本框、按钮和安全边距，无法证明宿主视口可见性。
- 不得只修改 `graph.size` 而不重新检查所有关键组件的可读尺寸、边距和位置。

用户提供编辑器截图或报告裁切问题时：

- 先判断是整图缩放/平移造成的视口裁切，还是组件包围盒之间的局部遮挡。
- 截图像素只有在缩放比例、画布原点、设备像素比和侧栏占用均已知时，才能换算为 Graph 坐标。
- 映射未知时不得从截图猜测缩放系数或平移量；优先回退到 `800×600` 和上述安全区重新排版。
- JSON 边界校验只能证明组件位于 Graph 内，不能单独证明它在宿主编辑器首屏可见。

## 5. HTML 页面层边界

- `graph.htmlCode` 本身没有原生 `position` 和 `size` 字段；HTML 页面应通过标准 HTML/CSS 布局适配其 HTML 渲染画布的可见区域。
- HTML 可见内容、iframe、HTML 图表、HTML 弹窗、HTML 动画和第三方网页内容必须适配 HTML 页面层的可见区域。
- HTML 页面不得产生无意义的水平滚动条、超出 HTML 页面层的关键内容或无法操作的关键交互区。
- HTML 内容内部允许滚动时，滚动区域必须明确，且不能使 HTML 页面主要控制或信息区域不可见。
- HTML 内部弹窗、悬浮卡片、全屏图表、iframe、滚动容器、图表和动态内容只需避免破坏 HTML 页面层自身的可读性与可操作性；不需要与原生组件层做避让或冲突检查。

## 6. 原生普通组件不得重叠

除“合法工艺重叠”外，以下原生普通组件之间不得发生包围盒交叉：

- 按钮、开关、复选框、输入框、输出框、选择器、滑动条。
- 文本、标签、单位文字、标题、说明文字。
- 仪表、进度条、趋势图、XY 图、表格。
- 不属于同一个复合工艺对象的基础图形。

原生组件层布局时应确保：

- 原生文本不覆盖原生按钮、输入框、输出框、仪表、图表或表格。
- 两个原生交互组件不相交。
- 原生标签、读数和单位文字之间不相互覆盖。
- 不同原生功能区域的普通组件不相交。
- 容器背景或边框不遮挡其视觉区域上的原生组件。
- 原生 PLC 控件不与其他原生组件发生不可用的重叠。

若两个普通原生组件的矩形包围盒存在交叉面积，则应重新布局；仅边缘接触时，也应优先保留可见间隔，除非用户明确要求紧贴。

HTML 页面中的关键文字、HTML 按钮、表格、图表和交互元素同样不得在 HTML 页面层内发生不可读、不可点击的重叠。

## 7. 合法工艺重叠

以下具有明确工艺语义的原生组件重叠允许存在：

- `base:circle` 滚筒位于输送带 `base:rect` 两端。
- `base:polyline` 的流动虚线位于输送带、管道或工艺路径上。
- 表示液面的图形位于水箱、储罐或容器轮廓内部。
- 阀门、泵、电机等复合工艺对象由多个基础图形组成。
- 状态灯、运行标识或局部标签紧邻或叠加在设备图标附近。
- `node:container` 作为底层背景，根级普通组件覆盖在其视觉区域内。
- HTML 中用于表达设备、管线、液面、流向、状态或数据关系的 SVG、Canvas、CSS 图层可在 HTML 页面层内进行合理的局部重叠。

合法工艺重叠必须满足：

- 叠加用于表达设备结构、工艺介质、流向、状态或层次关系。
- 同层关键控制与关键文本仍然可见、可读、可操作。
- 原生组件层级顺序合理：背景/外壳在前，介质/路径在中，状态/文字在后。
- `base:shape` 与 `base:polyline` 仍满足 `schema.md` 的 points、segments、pointsSize 规则。
- HTML 内的局部重叠不得遮挡其所属 HTML 对象的关键读数、报警文字或交互区域。

## 8. 分组与对齐

- 同一原生控制组中的按钮、开关、输入框和输出框应优先对齐。
- 相同功能的原生组件应优先使用相同尺寸；用户明确指定不同尺寸时按用户要求执行。
- 同一组原生标签应优先左对齐或右对齐；同一组读数框应优先对齐。
- 原生状态灯与对应状态文字应组成清晰的相邻关系。
- 当用户要求“并排”“上下排列”“居中”“靠左”“靠右”“顶部”“底部”等布局时，按其语义保持相应层内的对齐与顺序。
- 当用户未指定布局时，原生组件层应以功能关系、阅读顺序和避免重叠为依据自动排列。
- 原生控制组件应按操作顺序和工艺顺序排列，例如启动/停止、设定/确认、状态/报警。
- HTML 卡片、HTML 数据表、图表和外部数据区域应在 HTML 页面层内保持标题、筛选区、内容区、状态区之间的清晰结构。

## 9. 容器和页签

- `node:container` 只作为根级背景、边框或视觉分组区域使用。
- 普通组件不能放入 `node:container.children`；它们必须与容器并列放在 `graph.children` 中。
- 容器必须先于覆盖其视觉区域的组件出现在 `graph.children` 中，以确保容器作为原生层底层背景。
- 原生组件层信息量无法在同一画布内清晰呈现时，可使用 `node:tabView` 拆分页面。
- `node:tabView`、`node:tab` 的嵌套关系必须严格遵守 `schema.md`。
- 使用页签时，应将相关的原生工艺控制、参数设定和状态展示放在同一业务页签中。
- HTML 报表、第三方系统、摄像头或复杂分析内容可在 HTML 页面层中按其自身网页结构组织；是否使用原生页签由原生层信息结构和用户要求决定，而非因 HTML 内容占用空间而强制决定。

## 10. HTML 页面布局

- 完整 HTML 文档或头部/正文片段均可按渲染器已验证方式生成。
- CSS 通常放在 `<head>` 的 `<style>` 中，页面结构和脚本通常放在 `<body>` 中。
- HTML 可以使用卡片、网格、表格、表单、图表、SVG、Canvas、动画、iframe 和外部库实现复杂展示。
- HTML 内部可以使用合理嵌套、卡片、网格、表格、表单和局部视觉重叠，但关键文字、按钮、读数必须可见、可操作。
- iframe 宽高和页面内容应适配 HTML 页面层的可用区域。
- 目标网站加载失败或拒绝被嵌入时，不得视为 iframe 内容布局成功。
- HTML 的动画、图表、脚本更新和外部库渲染在任何状态下均不得裁剪 HTML 页面层内的关键内容或覆盖 HTML 页面层内的关键控制。
- HTML 没有已确认的第三方接口配置时，应展示接口占位、模拟数据或设计预览，不得伪造成现场 PLC 实时数据。

## 11. 原生组件与 HTML 混合页面规则

- `graph.children` 与 `graph.htmlCode` 已验证可在同一个 `graph` JSON 中并列生成，并由完全独立的环境分别渲染。
- 原生组件负责现场 PLC 控制、变量绑定、设备启停、参数输入、报警确认、现场状态、仪表、趋势和工艺控制。
- HTML 负责复杂展示、复杂报表、统计图、筛选表格、时间轴、摄像头、第三方 API、外部系统、iframe 和网页化交互。
- HTML 当前不读取、不订阅、不写入、不控制现场 PLC 变量，也不访问原生组件已绑定的 PLC 变量。
- 原生组件层与 HTML 页面层独立渲染。生成原生组件层时完全忽略 HTML 层；生成 HTML 页面层时完全忽略原生组件层。
- 每层都应根据自身需求、自己的画布或视口、内容密度和用户对该层的要求独立生成完整页面，不得根据另一层调整位置、尺寸或留白。
- 不得采用“左原生右 HTML”“上原生下 HTML”等跨层空间分区，也不得以另一层已占用某一区域为由减少本层内容。
- 原生组件的 PLC 数据与 HTML 的第三方数据、模拟数据或设计预览必须具有明确数据语义边界。
- 不得把 HTML 模拟数据、第三方 API 数据或外部系统数据伪造成原生组件 PLC 实时数据。
- 若用户明确要求同一业务页面既有 PLC 控制又有复杂报表、摄像头、第三方系统或外部数据，应优先规划混合页面，而不是删除任一侧功能。
- HTML 可以在其独立页面层内使用弹窗、悬浮卡片、全屏图表、iframe 和滚动容器；这些内容不构成对原生组件层的遮挡、点击或滚动冲突。
- 原生组件层与 HTML 页面层可使用统一的用户指定主题、颜色或排版风格，也可按业务需要采用不同视觉结构。

## 12. 动态元素布局

- 动态原生组件在其所有可见状态下均不得超出原生画布、遮挡原生关键文字或覆盖其他原生普通组件。
- 流动路径、液面、旋转标识和状态强调等动态视觉层可与所属原生工艺对象合法重叠，但不得覆盖该对象的关键控制、关键读数或报警文字。
- 为动态原生文本、读数变化和状态切换预留足够显示空间，避免状态变化后产生裁剪或重叠。
- 同一原生功能区域中的动态效果应保持清晰的视觉层级；背景、工艺主体、动态介质或路径、状态标识与文字应按其可读性安排层级。
- HTML 中可使用 CSS 动画、JavaScript 定时器、SVG、Canvas 或外部库实现第三方数据展示和设计预览动态。
- HTML 动态不得表现为未接入的现场 PLC 实时状态。
- 摄像头、外部系统和第三方 API 数据的加载状态、失败状态和占位状态应清晰显示，不得以静态内容冒充实时连接成功。
- 同一 HTML 页面中不应让过多持续动画同时争夺注意力；动态效果应服务于工艺、第三方数据状态或明确交互反馈。

## 13. 输出前布局检查

输出 JSON 前，必须检查：

1. 用户明确要求的尺寸、位置、主题、HTML、混合模式和布局已被优先执行。
2. 所有原生组件在画布或合法父节点范围内。
3. 所有 HTML 可见内容、iframe、图表、动画和外部页面内容适配 HTML 页面层可见区域。
4. 原生普通组件之间不存在包围盒交叉。
5. HTML 页面层内部的关键文字、按钮、表格、图表和交互元素不存在不可读、不可点击的重叠。
6. 原生层与 HTML 层分别在假设另一层不存在的前提下生成和校验；两层之间不参考坐标或尺寸，不执行避让、留白、缩小、包围盒碰撞、遮挡、点击或滚动冲突检查。
7. 合法重叠仅用于同层工艺复合图形、流向、液面、状态标识、HTML 工艺图层或原生容器背景。
8. HTML 模拟数据、第三方 API 数据和外部系统数据未被伪造成 PLC 实时数据。
9. 动态原生元素在全部可见状态下均未越界、未裁剪、未遮挡原生关键文字、关键读数或关键控制；HTML 动态内容在 HTML 页面层内保持可读、可见、可操作。
10. 同组原生组件保持合理的对齐和顺序；HTML 页面内部信息结构清晰。
11. 原生层空间不足时已重新布局、分组或使用页签，而不是制造重叠；HTML 页面层空间不足时已使用适当的响应式、折叠、分页或明确内部滚动方案。
12. 所有布局结果仍严格符合 `schema.md`。
13. 用户未指定画布时，`graph.size` 为 `800×600`，所有关键内容位于第 4.1 节的宿主视口安全区内。
14. 未使用扩大画布或全局机械缩放作为裁切修复；若曾出现裁切，已经重新排版并重新检查关键文本和控件尺寸。
